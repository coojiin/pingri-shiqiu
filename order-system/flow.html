展示原型 · 驗收流程

GitHub Pages 客戶端示範 · 無獨立 API · 正式版改跑店內 pingri-order-api

一、店長驗收（同一台筆電）

1
開 tables.html → PIN 1234 →「產生／輪替 Token」→ 可列印桌貼／櫃檯外帶 QR。
2
再開分頁 kitchen.html → 同一 PIN → 保持開著。
3
第三分頁掃 QR 或從 展示中心 進「桌 1 點餐」→ 選餐送出 → 廚房應立刻出現（BroadcastChannel／localStorage）。外帶有取餐號 T-###。

二、路徑一覽

路徑用途
index.html展示中心／一鍵示範
order.html?t=…客人點餐（自描述 Token）
tables.htmlToken QR 產生／列印
kitchen.html廚房出單板
flow.html本說明

三、技術界線（務必跟店長講清楚）

  • Token：簽名內含桌別／外帶，任一裝置可驗證（展示級 HMAC，非真實資安）。
  • 訂單：只存在該瀏覽器 localStorage；分頁間用 BroadcastChannel 同步。
  • 跨手機不會同步訂單——兩支手機各開廚房／點餐時看不到對方單。正式版需店內主機 API。
  • 不再使用公開 ?table=N 或無 Token 的 ?mode=takeout。
  • PIN 1234 僅前端常數 · 非正式登入。

四、訂單狀態

  • pending 待做
  • cooking 製作中
  • done 完成
  • call 餐畢叫店員

五、正式版路徑

店內 PC 安裝 pingri-order-api → 客人掃 LAN QR → 廚房／多裝置即時同步。本 Pages 原型僅供驗收 UI 與流程。
